# Agent Learnings

Operational learnings from supervised ticket-wave delivery. **Live document: delegated-wave supervisors and implementers must read this before starting wave work.** Update it after every wave that produces durable lessons; delete entries that stop being true instead of keeping history.

Source: renderer-v3 wave `ab6a85b4` (2026-08-11; #184/#186/#189/#193/#194/#196 — four merged, two parked to #215/#216).

## Verification and measurement

1. **Verify bytes, never displayed text.** The supervisor terminal wrapper silently drops comma-space sequences in all displayed output (grep, sed, od, read, git show). This made correct comma-separated CSS look "compound" for three review rounds; the fixer had landed the edit every time. For byte-critical claims (CSS selectors, literal strings, file equality) use Python byte counts (`d.count(b'...')`) or file hashes. Rule also documented in `docs/agents/delegated-delivery.md`.
2. **When the same fix "fails to land" repeatedly, suspect the measurement channel before the fixer.** Three identical failures were a corrupted read, not a broken write.
3. **Discriminating probes beat suite-green as evidence.** Build a minimal mutation that flips behavior between fixed and unfixed code (e.g. content that exceeds the stage budget only when the defect is present). It proves the fix works *and* produces no false positives. Keep the probe content calibrated: overshooting windows trigger unrelated overflows and destroy discrimination.
4. **Playwright full-deck audit tests flake under full-suite concurrency.** Before calling a regression, rerun the failing test standalone on both the PR head and main.

## Pipeline mechanics (no-mistakes + herdr)

5. **The pipeline owns the branch.** Fix-round commits live in daemon worktrees (`~/.no-mistakes/worktrees/<repo-hash>/<runId>/`); pane worktrees stay stale. Event-reported heads can be transient sync artifacts. Ground truth is the GitHub API `headRefOid` plus byte-level diffs; the push step rebases onto current main.
6. **Every merge to main CONFLICTS all other in-flight branches.** Budget one rebase pass per merge for each remaining ticket. Let the pipeline's AI-assisted rebase do union merges; hand-resolving 1000+ line diverged hunks is higher risk (aborted once in this wave).
7. **Parallel waves over shared files duplicate work.** #196 re-implemented #214's stacked-bar code because both cut from the same base. Sequence tickets that touch the same files, and tell rebasing implementers to prefer MAIN on overlap.
8. **herdr `BrokenPipe` (Windows error 232) is transient.** Retry once after a short sleep; confirm pane liveness with `herdr pane list` before assuming a pane died.
9. **Watcher dedup signatures must use stable fields only.** Heads advance per fixer commit and `axi status` summary strings churn on parse wobble (the false update banner on stderr); both flooded follow-ups. Stable axes: run + breached-kind + review-fix-round for loop limits; run + head + finding-count for parked gates.
10. **PowerShell traps:** pass int arrays via `pwsh -Command "& script -Issue 1,2,3"` (not `-File` with commas); backticks inside double-quoted here-strings are consumed as escapes and silently corrupt generated prompts (this garbled every implementer contract for an entire wave generation) — render generated templates and inspect them, not just parse-check; Python on Windows needs `%LOCALAPPDATA%`-style paths, and UTF-8 output needs explicit encoding.
11. **A fresh pane's input pipe can die while reads stay healthy.** Pane launched, brief text visible in the editor, but 0.0% context and `idle`; `send-keys`/`send-text`/`pane close` all fail BrokenPipe 232 even after retry, while `pane list`/`read`/`process-info` work. The launcher swallows send-keys errors, so `implementing` state in wave.json is not proof of submission — verify context % > 0 / `working` before trusting a launch. Recovery that worked: `pane close` (retry until it lands), confirm the Pi process is gone, rerun `launch-visible-implementer.ps1` on the same run-owned worktree, then sync the new `tab`/`pane` ids in `wave.json` and `targets.json`; watcher-state stays clean because the dead pane's idle event was suppressed-informal and never persisted. Recurred on wave c192e83b (#188) — systemic in start-ticket-wave.ps1's ENTER injection, not one-off; launch-visible-implementer.ps1 has injected cleanly both times. This wave's dead-pane close also needed a BrokenPipe retry, same as the first.
12. **Layout index staleness is a recurring CI class.** Any fixture change requires regenerating `wiki/renderer_v2_LAYOUTS.md` via `scripts/gen_layout_index.py`; every branch in the wave hit this once.

## Supervision and escalation

13. **Contract wording alone does not bind implementers.** All six early parked gates were self-decided by implementers despite explicit "escalate, never decide" text. What worked: explicit parked-gate parking rules + relay-execution-exactly rules + live relays into active panes + md5-pinned staged files the pane only copies. Delegate verified artifacts, not decisions.
14. **Park with a pre-staged recovery.** Before releasing a parked pane: implement and host-verify the next fix yourself, commit it on a recovery branch, stage the file md5-pinned in `%LOCALAPPDATA%\Temp\`, and rewrite the follow-up issue with exact resume head, outstanding finding, repro, and tooling notes. Parking is then a state, not a loss.
15. **When the supervisor authors the code, the supervisor owns its findings.** Late-round defects came from supervisor-staged fixes; the honest move is to verify and relay the correction under an explicit hard stop, not to invoke the stop selectively.
16. **Hard stops need user consent per exception round.** State the stop, report the new finding with an A/B recommendation, and let the user authorize any further round. Batched approvals with explicit options and a recommendation keep long waves moving on few user tokens.
17. **Intentional parks require stopping the wave watcher**, or quiet-limit escalation events re-escalate the parked gate as noise.

## Renderer-v3 architecture

18. **Fit/paint CSS parity is the systemic defect class of this renderer.** Constants must be read from the emitted CSS in `publish.py` (e.g. padding 12 vs a fitter's `CARD_PAD` 16), including flex gaps, per-element margins, and list indent (`ul` padding-left plus global `li` margin-left stacks). Incremental finding-by-finding fixes cannot converge on a systemic class; after 2-3 findings in one family, park to a focused audit ticket. Collapse stacked list indents to one `LIST_INDENT_EM`; always-on trailing margins (`.item-statement` mb 4) count even without detail. Frozen chart `view_h`/`pad_b` stay allocation-owned: a relocated context block must fit the existing below-plot pad or strict-fail — never grow the view after `plot_h` freeze.
19. **Mirror failure: chrome double-counting.** Once a fitter returns full painted height *including* card padding, the plan's `_chrome_h` for that surface must be zero, or dual-band math adds the padding twice. Whenever a fit function changes what it includes, audit every `_chrome_h` consumer.
20. **Clamps need membership-accurate filters.** The hero_restore stage clamp first filtered siblings by `layout_type` (matched everything on the slide → no-op), then by `_chart_spec is None` (over-counted left-column support inside `left_total` → false clamps). Correct set = same-slide surfaces minus the dual-band members (chart/hero/support from the slot map). Prove both directions: false-clamp windows go clean, true overages still fail strict with `plan.unresolved_overflow`.
21. **Measurement architecture: per-row fitters for mixed-size boards.** `hero_card`/`metric_overview` paint mixed font sizes and CSS gaps; a single-size `_required_height` collapses them. Model each painted row with its role size plus the exact painted gaps/margins (see `_hero_fit_height` / `_metric_overview_fit_height`), and keep newline unit sentinels between text groups so `_split_units` measures per row.
22. **Watcher event delivery binds to the launching session only.** `start-ticket-wave.ps1` records the supervising `PI_SESSION_ID` in the active-wave registry; `ticket-wave-followups.ts` delivers only to that exact session. If the wave outlives its launching session, events keep queueing in `host-followup.txt` but nothing arrives in-session. Diagnose via the registry `sessionId` vs the current session and a stale `actions.jsonl`; verify per-event disposition there. `resume-ticket-wave.ps1` now rebinds registry + manifest `sessionId` to `$env:PI_SESSION_ID` (with `reboundSessionId` in its output); resumed backlog is intentionally not re-delivered (extension binds at EOF).
23. **`axi respond --findings` takes comma-separated ids in one value.** Space-separated ids parse as subcommands and the call dies with `unknown command "<second id>"` before consuming the gate (verified 2026-08-12, run 01KZSCB9). Always pass `--findings id1,id2,id3`; confirm consumption via run status/`step_results`, not just the exit code of the detached launcher.
24. **`axi respond` resolves the run from the current git branch, no `--run` flag.** From a non-repo cwd it dies with `not in a git repository`; from a repo on the wrong branch with `no active run to respond to`. Run it from a checkout whose branch is the run's branch (the pane worktree works, even when its head is ahead of the reviewed head). Verify consumption via run status (`review: fixing`), not the respond exit code. `--action fix` also accepts `--instructions <text>` (guidance applied to the selected findings) and `--add-finding <json>`; use `--instructions` to relay author design decisions for ask-user findings instead of letting the fixer guess (wave c192e83b round 3: omit-chrome decision for last-slot overlap).
25. **A parked-gate event with `rearm:false` terminates the whole watcher.** The `ask-user-paused` / `await-explicit-ticket-resume` event is emitted once, then the outer loop breaks by design (anti-noise, cf. #16) — and it is not delivered as an in-session follow-up, so the supervisor can easily miss that supervision ended. After relaying any decision that resumes a run, restart the watcher (`watch-ticket-wave.ps1 -ManifestPath <wave.json>`; the mutex is released on clean exit) or the next gate parks silently — verified: the fix-review gate sat parked 3h15m with zero notifications. The backgrounded `axi respond` log does capture the next gate, but a log cannot wake anyone; treat it as receipt, not monitor.
26. **Watcher `review-fixing-minutes` counted gate-park time.** The loop-limit counter took max(steps[] cumulative ms, active_steps human duration); the human `active_for` includes parked awaiting-approval waiting (observed 3h16m of gate wait inflating a fresh 10-min reviewer to 4h12m and tripping the 90-min limit). Fixed in `watch-visible-implementers.ps1`: steps[] cumulative ms is authoritative (it stays frozen while parked); active_steps parsing is only a fallback when steps[] is absent. Verified 20.7 vs 252 on the captured status text. If a loop-limit fires right after a long gate park, suspect this class of false positive before treating the run as stuck — check commit timestamps and last_activity first.
27. **First PR creation detonated two latent watcher bugs; pr-ready never arrived.** Chain: no-mistakes created PR #220 without a `Closes #185` reference; the watcher correctly tried to emit `metadata-blocked`; `Get-WaveCloseState`'s `return ,@($states)` double-wrapped against the caller's `@(...)`, so `$missingClosing[0]` was the inner Object[]; `ForEach-Object { $_.Issue }` survived via member enumeration but `@($missingClosing.Issue)` threw PropertyNotFoundStrict under StrictMode-2; the inner exited non-zero, the outer threw and exited — no restart mechanism, so supervision silently ended and pr-ready was never delivered. Reproduced exactly in a harness (count=1 type0=Object[] → CRASH). Fixes: flat `return @($states)` (verified n=1/2/0), added `Closes #185.` to PR #220 via `gh pr edit`, cleared stale `closing-reference` dedup key, restarted watcher; pr-ready then delivered on first poll. Standing checks: after any PR appears, verify its body carries the closing reference (`gh pr view N --json body`); if watcher events stop, check `watcher-restart*.log` for a dead outer before trusting silence.
28. **Extension allow-list silently ate a parked gate.** `ticket-wave-followups.ts` `isDecisionRelevant` only knew ask-user/pr-ready/loop-limit (+implementer-done); the watcher's `gate-parked` event for a parked fix_review gate was consumed as `reason=informational` and the offset advanced past it — 1h49m silent park on wave c192e83b until a manual status probe found it. Fixed by adding every decision-class watcher type (gate-parked, metadata-blocked, cleanup-blocked/failed/complete) to the allow-list; requires `/reload` or a new session to activate. Standing checks: the allow-list must mirror the watcher's `type =` emit sites (grep both when either changes); when `axi status` shows `awaiting_agent: parked` but no event arrived, grep the wave's actions.jsonl for `suppressed reason=informational`.

29. **Pipeline fix rounds drift generated artifacts only CI checks** (#188, wave c192e83b): review fix rounds edited `models.py` (waterfall validator) but nothing regenerated `impact_slides/renderer_v3/schema/handoff_schema_v1.json`; the local pipeline `test` step runs pytest only, so the drift surfaced as CI failure after push. Same class: `wiki/renderer_v2_LAYOUTS.md` stale from an unrelated merge (#215) failing every subsequent CI. The ci step self-heals both via `no-mistakes: apply CI fixes` commits (one push per stale artifact) without rounds or decisions. Standing checks: after any review round touching `models.py`, expect schema drift; after merges touching renderer_v2 recipes, expect layout-index drift; let the ci self-heal loop run, then confirm the PR head is stable and re-verify the closing reference before merge approval.

30. **Teardown needs a manual fallback pass when herdr is flaky** (second occurrence, #221 teardown): `teardown-ticket-wave.ps1 -Apply` aborts partially when `herdr pane list` fails or Pi still holds the worktree — registry, wave root, worktree, or daemon worktrees stay behind. Manual closeout order that works: close the pane with one retry (BrokenPipe 232 is flaky), confirm zero node processes matching the worktree, `git worktree remove --force`, `git branch -D` the run branch, filter the run out of `active-waves.json`, `rm -rf` the wave root, and sweep listed orphan daemon worktrees. Verify with `ls` + registry count, not teardown output. A manually restarted watcher is invisible to teardown (wave.json only knows the launch PID) and its poll children hold the worktree cwd, so `git worktree remove` fails with permission denied; kill processes matching `watch-ticket-wave|watch-visible-implementers` first.

31. **ask-user-paused rearm:false silently kills the watcher even when deduped** (#198, wave 04cafbac): the second ask-user notification for an unchanged decision emits `ask-user-paused` with `rearm:false`; the outer loop breaks on it and dies. On #185 the event was delivered first (lesson 25); on #198 the event was dedup-suppressed (actions.jsonl says `suppressed`) yet still broke the loop — an overnight r6 park went unnotified. It also raced a relay by seconds: the paused snapshot still showed the old gate while the fix was already consumed. Fix applied: paused events now carry `rearm:true` — "pause" only means stop re-notifying the same decision (the signature dedupe enforces that); the watcher keeps covering new findings/heads/pr-ready. Standing check: if gates go quiet, confirm the watcher is alive before trusting silence.
32. **Stacked 1920×1080 slides screenshot as one cover if you only toggle `.active`** (wave 04cafbac, #198): v3 CSS has no `.active` hide rule and a fit script scales every section. Isolate one `section.slide` (`display:none` on siblings, reset stage transform) and screenshot that node; then hash-count unique PNGs. 88 identical files passed suite-green until that check.
33. **Stale-base squash merges can silently revert host-side doc files** (#198 teardown): PR branches based on older main carry an old `wiki/AGENT_LEARNINGS.md`; when their document step edits it, the squash merge's file diff clobbered lessons 23-31 on origin/main — the loss surfaced only as a stash-pop conflict on the next pull. Standing check after every squash merge: `git diff <pre-merge-main>..HEAD -- wiki/AGENT_LEARNINGS.md AGENTS.md` must show no vanished host-side entries; never `git pull --autostash` over uncommitted learnings without inspecting the pop for markers.
34. **`start-ticket-wave.ps1` workspace auto-detect crashes if any Herdr workspace lacks a `worktree` property.** Strict-mode `Where-Object` on `$_.worktree` throws PropertyNotFoundStrict and the launch dies before worktrees exist (wave 9ba968a4: a plain Herdr workspace without a worktree killed auto-detect; the retry then hit a 900s bash timeout while the script actually completed in the background). Launch with explicit `-WorkspaceId <id>` whenever any workspace in the Herdr list is not worktree-backed; on apparent timeout, check the active-wave registry + `herdr pane list` before relaunching — the wave may already be up.
35. **`herdr pane send-text` has no `--submit`; a stray flag is injected as literal text.** To submit a relay: `herdr pane send-text <pane> --text "..."` then `herdr pane send-keys <pane> Enter` as a separate call. Verify the pane flips idle→working; a `done` pane can still accept buffered text + Enter (its session wakes to process it).
36. **Parked gates on `done` panes are watcher-invisible even with the lesson-28 allow-list.** `ask-user-paused|<issue>|done|...` was classified informational and dedup-suppressed (actions.jsonl shows it), so the #232 review gate sat parked ~30m unnotified. Standing check: when an implementer pane is `done` but its run is `running`, poll `axi status` directly on decision-relevant triggers (merge landed, loop-limit, previous gate consumed) — do not trust event silence.
37. **The no-mistakes daemon can die mid-wave; state survives, respond calls don't.** `axi respond` fails with `daemon process <pid> is no longer running (run 'no-mistakes daemon start' to recover)` — start the daemon and re-issue the exact respond (run state, gates, and findings persist). Pipeline push/PR credentials are independent of the supervisor's `gh` token: PRs kept flowing while the supervisor `gh` was 401 (keyring token expiry). If `gh auth status` fails mid-wave with no GH_* env override, the Windows Credential Manager entry is stale — user must redo `gh auth login` and complete the flow; `hosts.yml` alone (account, no token) means the login never landed.
38. **Review-fix loops on emission-invariant finding families converge slowly; cap at 3 consents.** #232 legal_notice: rounds produced 2 → 1 → 1 → 1 findings across ~4h and tripped the 90-min loop-limit on gate-park-inflated minutes (cf. lesson 26). Strategy that worked: user-consented fix rounds up to 3, then approve the step and carry the residual same-class finding verbatim into a scoped follow-up ticket (#238). Each forced rebase re-verified via `git range-diff <oldbase>..<oldhead> <newbase>..<newhead>` — expect only doc/union deltas and acceptance-hash shifts, no source drift.
39. **The auto-launched watcher can die within a minute and leave zero trace in-session** (wave 89669a76): `watcherPid` in wave.json pointed at a dead PID, actions.jsonl held one suppressed startup event, watcher-state.json was `{}`, stderr empty, no watcher-restart log. All gates/PRs went unnotified until manual probing. Standing check after every wave launch (and after any long quiet stretch): confirm the watcherPid process is alive (`Get-Process -Id`); if dead, restart `watch-ticket-wave.ps1 -ManifestPath <wave.json>` — the restarted watcher replays backlogged decisions (it delivered the parked-gate and pr-ready backlog immediately). Root cause unknown; treat watcher liveness as untrusted until verified.
40. **Missing closing references keep recurring at PR creation — check immediately, don't wait for metadata-blocked.** Second occurrence (#239, after #220): the pr step opens the PR without `Closes #N` in the body; `closingIssuesReferences: []`. Fix is `gh pr edit N --body` appending `Closes #<issue>.` (GitHub computes the reference within seconds). Verify with `gh pr view N --json closingIssuesReferences` right after every pr-ready event, before preflight — the watcher's metadata-blocked delivery can race or lag the manual fix (a stale metadata-blocked for an already-fixed PR is benign; confirm current state and move on).
41. **`outlined_support` paints `stub_header.label`, not the row label.** `_outlined_support_plan` copies `table.stub_header.label` into `table_paint["label"]`; a v2 secondary table whose header stub is empty/`Metric` will paint `Metric` even when the one data row is `Reserve Rate for Total Balances`. For one-row outlined furniture, set `stub_header` to the row label (or assert the painted label, not just the row JSON). Verified on #227 s15.
42. **Leftover idle implementer panes survive teardown and hold the empty worktree dirs** (waves 9ba968a4/262c6f74): teardown's pane-close can leave the pane alive in `idle`; its shell cwd then keeps the emptied worktree directory undeletable ("Device or resource busy"). After every teardown: `herdr pane list`, close any pane whose cwd is a torn-down worktree, then `rm -rf` the dir — it goes away immediately.
43. **Returned-PR repairs go through `orchestrate-herdr-repair-visible.ps1` with a host-findings brief.** Verified on #229/PR #243 (Option-B spec restoration): `-RunId` is the PEW wave run id (lowercase hex), not the axi run id (validation rejects uppercase base32); the repair pane starts a fresh axi run in the same worktree and re-drives push/PR/CI. Two follow-up duties after every repair pr-ready: (a) the repair push can overwrite the PR body — re-check/restore the closing reference; (b) re-request approval, the old exact-head approval is void.
44. **Teardown's orphan daemon-worktree sweep crashes on `nul` files (second occurrence).** Completed no-mistakes agent runs leave a file literally named `nul` under `%USERPROFILE%\.no-mistakes\worktrees\<id>\<run-id>\` (likely a stray `> nul` redirect from a pi-spawned shell); PowerShell's sweep dies with "Incorrect function", after deregistering the wave but before deleting the wave root. Deeper finding (wave ac2e27c8): the `nul` file is undeletable through every standard tool — cmd `del`/`ren`, PowerShell, and Python all normalize the path to the NUL device (`\\.\nul`, access denied) even with the `\\?\` prefix. Stop after one attempt: the orphaned daemon-worktree dir is inert (finished run, nothing references it). Manual completion = verify registry empty + branches/worktrees gone, delete the leftover wave root by hand, leave the `nul` dir for a reboot or a raw Win32 DeleteFileW tool. Registry/worktree/branch state is already clean at the crash point — verify before assuming failure.
45. **OpenRouter credit caps kill implementer panes silently: `402 Prompt tokens limit exceeded` (limit_source openrouter_credits).** Observed on #233: the pane died mid-edit with uncommitted work, no push, no axi run; the watcher delivered a benign-looking `done` event ("no no-mistakes run for branch"). Diagnosis: `herdr pane read <pane>` tail shows the 402 before the compaction banner. Recovery: user tops up credits (openrouter.ai/settings/credits), then launch a repair pane whose brief lists the uncommitted partial files to pick up. If a 402 recurs, stop and escalate — no retry loops.
46. **herdr `workspace list` dropped the `worktree` metadata field** (wave b3cc3a8a): `start-ticket-wave.ps1` workspace resolution threw on `$_.worktree` access and blocked launch. Fix landed in the script: filter focused workspaces by `repo_root` when `worktree` metadata exists, else fall back to the focused set and let the exactly-one count check guard. Expect herdr schema drift in launch scripts; validate against current `herdr workspace list` output before assuming script bugs.
47. **Missing closing references are now watcher-compensated, but the root cause lives in the no-mistakes `pr` step.** Four consecutive PRs (#220, #239, #250, #251) opened without `Closes #N`. `watch-visible-implementers.ps1` now repairs the reference deterministically at pr-ready (once per run/head/PR; new heads re-trigger, covering repair re-pushes). Deeper fix = make the daemon's pr step include the reference; deferred because rebuilding/restarting the custom daemon mid-wave is unsafe (active runs). The pi-extensible-workflows scripts moved to `~/.pi/agent/delegated-delivery/` during wave b3cc3a8a; wave.json `watcherScript` was migrated, but the old-path outer watcher died silently — verify watcher liveness (lesson 39) after any tooling move.
48. **Wave b3cc3a8a closeout mechanics.** (a) Serial merges within one wave guarantee N-1 conflict-repair rounds: the pipeline rebases only at run start, so every later PR needs an `orchestrate-herdr-repair-visible.ps1` union rebase after earlier merges land (#246 and #248 both needed it). Union policy: docs keep both sides; disjoint source regions keep both behaviors; acceptance-bundle JSON is never hand-merged — regenerate from merged source. (b) `teardown-ticket-wave.ps1` dies on daemon worktrees containing Windows reserved names (`nul`): fix is `os.scandir`/`os.remove` with a `\?\` UNC prefix, then rmdir; teardown also leaves local ticket branch refs behind — `git branch -D` after content is squash-merged. (c) The watcher's pr-ready closing-reference auto-repair (learning 47) worked in the field three times; no hand-edits were needed after deployment.
